# Documents

These are point-in-time design records. They describe what was intended when
they were written, and they are not updated as the code moves on. Nothing here
is authoritative about how orange behaves today.

For current state, read these instead:

| Question | Document |
| --- | --- |
| What does it do, and how do I run it? | [`README.md`](../README.md) |
| Where does the code live, and what owns what? | [`ARCHITECTURE.md`](../ARCHITECTURE.md) |
| How do I work on it on this machine? | [`AGENTS.md`](../AGENTS.md) |

| Directory | Contents |
| --- | --- |
| `specs/` | What a change was meant to achieve, and why, agreed before the work |
| `plans/` | The task-by-task breakdown that implemented a spec |

Both are named `YYYY-MM-DD-topic.md` after the date the work started, and a plan
names the spec it implements at the top.
