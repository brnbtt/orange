# Orange Website Implementation Plan

**Goal:** Give people a simple, shareable Orange website with the latest Windows download, hosted economically on Azure.

**Architecture:** Serve plain HTML, CSS, and JavaScript from the existing release storage account's `$web` container. Read the published beta manifest in the browser, with a narrowly scoped Blob CORS rule, so each release updates the download destination without redeploying the website. Retain a GitHub releases fallback when JavaScript or the manifest is unavailable.

**Tech stack:** Native HTML/CSS/JavaScript, Node's built-in test runner, PowerShell, Azure CLI, Azure Storage static website hosting.

**Spec:** User request in this session: simple app website, latest-version download, Azure deployment, minimal spending and reuse of existing resources.

## Constraints and visual direction

- Reuse `orangealpha0d8d5893e69a3` in `orange-rg`; no new compute service.
- Keep the beta manifest and immutable installers as the release authority.
- Use the existing logo and desktop palette: charcoal `#0d0d10`, sand `#e6e0d1`, orange `#ff5a1f`.
- Use a spacious hero, a clearly labelled illustrative streaming scene, three benefits, three setup steps, concise FAQs, and a repeated download action.
- Native system fonts, visible keyboard focus, 44px targets, responsive layout, and reduced-motion support.
- Identify the download as beta and Windows 10/11 x64; make no unmeasured performance claims.
